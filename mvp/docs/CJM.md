# Путь показа песочницы

Обновление 17.10.2026, версия 0.4.1: закрытая покупка в demo пропускается с пояснением до подтверждения и на результате. Её сумма остаётся в рублях. «Пересчитать оставшиеся покупки» использует прежний счёт и новое подтверждение; «Начать заново» создаёт новый счёт. Если все покупки закрыты, приложение объясняет причину и не создаёт предложение. [Сценарий сегодняшнего показа](DEMO.md). Ниже — исходный путь 0.4.0; его шаги сохраняются.

Срез: 16.10.2026, версия 0.4.0, D-010. Пользователь потребовал короткий понятный demo без анкеты опыта/долгов/подушки и переключателей Stop/Resume. Ниже — реализованный путь; его удобство проверено браузером, исследования на участниках ещё нет.

| Шаг | Что видит человек | Что делает приложение |
|---|---|---|
| 1. Первый экран | Токен, четыре карточки риска, цель и будущий состав | Пользу и состав можно изучить до подключения |
| 2. Риск | Осторожный / Умеренный / Сбалансированный / Динамичный | Диаграмма и доли меняются сразу; выбор ничего не покупает |
| 3. Цель | Название, сумма, срок, взнос | Арифметика стартовых10млн и взносов без доходности; разрыв не маскируется прогнозом |
| 4. Конкретный план | «Показать покупки» | Создание нового счёта10млн, если его нет; расчёт целых лотов, лимитов и известных расходов |
| 5. Одно подтверждение | Бумаги, штуки/лоты, цены, комиссия, запас бюджета | «Купить активы» подтверждает ровно это предложение и настройки; неизвестная комиссия блокирует покупку |
| 6. Результат | Очередь → статусы → «Портфель собран» | Показываются подтверждённые fills. Готовность требует совпадения snapshot с ledger, а не только времени ответа |
| 7. Повтор показа | «Начать заново» | Явное создание чистого виртуального счёта с10млн, прежний счёт/аудит сохраняются; повтор запроса не создаёт второй счёт |

В UI нет учебных/локальных пояснений, full-profile анкеты, отдельного Apply/Resume/Stop, ручных ордеров и выбора режима котировок. Цены последней доступной сессии записываются в proposal и коротко обозначаются на подтверждении. Токен в password-поле очищается после отправки. Для настройки нового счёта используется отдельный demo_config; основной профиль пользователя не копируется.

Сильнейший контраргумент: четырёх фиксированных риск-корзин недостаточно для индивидуального инвестиционного профилирования. Поэтому это sandbox-путь и отдельная конфигурация, а не замена целевого suitability для реальных денег. Контроли UUID, точного согласия, резервов/расходов, неизвестного исхода, сверки и остановки в backend сохранены.

Широкая и мобильная компоновка, покупка и повторный старт проверены с FakeSandbox на отдельной базе. Исторический фактический sandbox-прогон четырёх покупок описан отдельно; новая UI-проверка не выдаётся за новый брокерский прогон. Реальный счёт остаётся в режиме просмотра.
